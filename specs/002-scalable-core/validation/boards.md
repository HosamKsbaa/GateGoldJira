## Native board services and contracts (T027–T030)

Native columns expose named configuration/stage identities, grouped workflow mappings, full saved-view counts and board-owned order revisions. Ranked and unranked queries are separate prepared SQL paths; a full ranked page skips the tail, and an unranked cursor skips the ranked branch. Caller/layout/order/graph/filter/calendar context binds continuation; terminal pages are explicit. Counts for a card request cover its selected column. Without temporary filters, the saved count is reused rather than executed twice. Request-local custom planning resolves optional-filter selectivity, with numeric and literal rules shared with issue search.

Native movement delegates issue transitions to the existing canonical service inside the same transaction. Ambiguous grouped destinations require a stage ID; anchors must remain visible and mapped. Reordering only edits board ranks and column order. It retains issue content, backlog and graph revisions, supports precise bigint ranks, stable replay, bounded prefix promotion and batched rebalancing. The 2,000-card safety bound rejects oversized dense repairs instead of performing an unbounded rewrite. Shared-lifecycle reorders lock their sorted columns and issue/anchor rows; an actual held-column fixture proves another board can reorder independently. Stage-entry/exit invalidates affected column cursors on every mapped board without copying global ranks.

The application runner installs the board capacity guard before focused issue locks and checks the complete mutation before commit. This includes imports, organization/archive/backlog/restore, workflow migration, creation and automation-derived field changes. Metadata narrows capacity locks to its stable current stage; all locks are sorted. A competing priority-entry test admits one winner for the last slot and leaves no revision/event for the denied transaction. Creation and restoration cannot exceed a cap; reductions and unchanged saves remain allowed. Relative self/clock/dependency filters remain warning-only. Board configuration cannot introduce an overfull hard cap or remove required default-board stage coverage.

Six additive V2 operations expose layout reads, phased card pages, board creation, layout save, movement and reordering through the same REST/MCP services. Old core board reads/edit/create receive explicit client-upgrade guidance on modern projects; accepted old retry receipts remain replayable behind current access. Workflow coverage uses normalized mappings after cutover. Clients and sqlc outputs regenerated; import boundaries and reproducibility checks pass.
