# Plan

Reuse the account credential/activity store as the stable connection identity, distinguishing personal tokens and OAuth grants. Add a durable, indexed OAuth protocol store with hashed credentials; no raw access/refresh tokens or codes in persistence. Use pinned go-oauth2 v4.6.0 for protocol processing with a PostgreSQL transaction per exchange, locked credential reads, mandatory PKCE, short expirations, and a restricted static client registry. Expose a typed REST consent API to Angular; the public authorization endpoint redirects only to the configured local app consent route. Only register local authorization endpoints when existing development/password loopback checks pass.

Constitution check: typed DTOs, generated Huma/sqlc clients, separate Angular/Go apps, same transactional business services, current permissions, persistent PostgreSQL state, bounded requests and queries. No new infrastructure or production identity service. Security tests cover consent, binding, concurrency, reuse, refresh, audit and revocation. Run frontend checks/build, Go checks, PostgreSQL integration/migration tests and an isolated browser flow. Update Antigravity configs without exposing secrets or overwriting unrelated servers.

Protocol endpoints are public authentication boundaries, separate from the business REST/MCP catalog. Existing account routes remain compatible. Additive migration; rollback must retire outstanding OAuth credentials before removing protocol storage. Local adapter is excluded from production. Managed-provider deployment remains separately configured.
